Question 1 · HashMap

How does HashMap work?

A box of small boxes. Give it a key, get back a value, very fast.

Must knowHashMapspeak 60s7 lessons

01One sentence

Say this first A HashMap is a box of small boxes. You give it a key (a name), and it gives you back a value (a thing) very fast. Inside, it uses an array. Each box in the array is called a bucket. When two keys fall into the same bucket, they stand in a line.

On the outside it looks like a table of names and values:

03How put works

When you call map.put("apple", 5), six things happen:

  1. Make the table — the first put creates the array with 16 buckets. (Before that, it is empty.)
  2. Compute the hash — a number from the key: (h = key.hashCode()) ^ (h >>> 16). The second half mixes the high bits into the low bits, so the number spreads better.
  3. Find the bucket — index = (n - 1) & hash. Because n is a power of two, this is the same as hash % n, but faster.
  4. Empty bucket? — put a new node there. Done.
  5. Not empty? — compare the key: same key → replace the value; different key → go to the end of the line and add a new node. If the line reaches 8 items, the bucket may become a tree.
  6. Too full? — if size > capacity × 0.75, double the array and move the items.
if ((tab = table) == null || (n = tab.length) == 0)
    n = (tab = resize()).length;                  // 1. create the array
if ((p = tab[i = (n - 1) & hash]) == null)
    tab[i] = newNode(hash, key, value, null);     // 2. empty bucket
else {
    if (p.hash == hash && (p.key == key || key.equals(p.key)))
        e = p;                                    // 3. same key: replace
    else if (p instanceof TreeNode)
        e = ((TreeNode<K,V>) p).putTreeVal(...);   // 4. bucket is a tree
    else {
        for (int binCount = 0; ; ++binCount) {
            if ((e = p.next) == null) {
                p.next = newNode(hash, key, value, null);  // 5. add at the end
                if (binCount >= TREEIFY_THRESHOLD - 1)
                    treeifyBin(tab, hash);                 //    line is long: tree
                break;
            }
            if (e.hash == hash && (e.key == key || key.equals(e.key))) break;
            p = e;
        }
    }
    if (e != null) { V old = e.value; e.value = value; return old; }
}
++modCount;
if (++size > threshold) resize();                 // 6. too full: grow
return null;

04Why resize is cheap

When the array grows from 16 to 32, an item has only two possible new places: where it is, or where it is + 16. One bit decides:

if ((e.hash & oldCap) == 0)  keep the item at index i
else                          move it to index i + oldCap

So HashMap does not recompute the hash or the index for every item. It splits each bucket into two small lines and moves them.

05Two numbers: 0.75 and 8

NumberWhat it meansWhy
0.75load factor: grow when size > capacity × 0.75A balance: smaller wastes memory, bigger makes more collisions. 0.75 is the usual middle.
8a bucket with 8 items may become a treeWith a good hash, a line of 8 is very rare (about 1 in 10,000,000). If it happens, the bucket is unlucky, so a tree makes it fast again.
64the array must have 64 buckets before a tree is allowedWith a small array it is cheaper to grow the array than to build a tree.
6a tree with 6 items turns back into a lineA buffer, so the bucket does not flip between tree and line again and again.

06Why it is not thread-safe

Two threads can call put at the same time. Both read the same size, both write it back — one increase is lost. In JDK 7, two threads resizing at once could even bend the lines into a circle, and then get would spin forever.

So in a web application use ConcurrentHashMap. It locks only the bucket that is being changed, not the whole map.

07Say it in 60 seconds

Read it out loud · then say it in your own words

A HashMap is an array of buckets. You give it a key, it computes a hash, and the hash tells it which bucket to use.

If the bucket is empty, the value goes in. If the bucket already has items with different keys, they stand in a line — a linked list. When one line reaches 8 items and the array has at least 64 buckets, the line becomes a red-black tree, so the worst case is O(log n) instead of O(n).

When the map is 75 percent full, the array doubles. Because the size is a power of two, each item either stays in its bucket or moves to bucket + old size, so there is no need to recompute the hash.

HashMap is fast and simple, but it is not thread-safe. In a web application I would use ConcurrentHashMap instead.
