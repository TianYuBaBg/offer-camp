How JDK 7 turned a resize into a ring.JDK 7 是怎么把一次扩容变成环的。

Head insertion plus concurrent resize can make two nodes point at each other forever.头插法碰上并发扩容，可能让两个节点互相指向，永远转不出来。

Short answer先给答案JDK 7 linked new nodes at the head of the chain. Two threads resizing at once could interleave so that A.next = B and B.next = A. Any later get() into that bucket loops forever, burning 100% CPU.JDK 7 用头插法挂新节点。两个线程同时扩容时，可能交错成 A.next = B 且 B.next = A。之后任何 get 落到这个桶，就会在环里死转，CPU 打满。

must know必背3 min3 分钟

01Why head insertion is the problem为什么问题出在头插法

// 头插：新节点总插到链头
for (Entry e : oldTable[i]) {
    Entry next = e.next;   // 记住下一个
    e.next = newTable[j];  // 插到新表链头
    newTable[j] = e;       // 成为新的头
    e = next;
}

// 两个线程交错执行时，e.next 可能指回已经搬过的节点

JDK 8 keeps the relative order (tail insertion + lo/hi split), so a ring cannot form. It still loses updates under concurrency — just without the infinite loop.JDK 8 保持相对顺序（尾插 + lo/hi 拆分），不会成环。但并发下依然会丢更新——只是不再死循环。

02What to say about it面试怎么用这条

Question is usually “is HashMap thread safe?”. Answer: no; JDK 7 could hang, JDK 8 loses data. Either way the fix is the same: use ConcurrentHashMap.这题通常问“HashMap 线程安全吗”。答：不安全；JDK 7 会挂死，JDK 8 会丢数据。不管哪种，解法都一样：换 ConcurrentHashMap。

Say it like this面试就这么说
