The lock reduces collisions; the CAS removes them.锁减少碰撞，CAS 消除碰撞。

Both instances may pull the same order id. A per-order lock makes one of them skip; the CAS makes the second one harmless even if the lock fails.两个实例可能同时取到同一个订单号。按单加锁让其中一个让路；就算锁失效，CAS 也让第二个变空操作。

Short answer先给答案Lock key is per order (lock:order:close:), not global — a global lock serialises the whole system. Inside the lock: read status, conditional update, restore stock, ZREM. Outside: nothing.锁的 key 按订单维度（lock:order:close:），不能全局——全局锁会把整站串起来。锁内做：读状态、条件更新、回补库存、ZREM；锁外不做业务。

01Inside the lock锁里做什么

lock = redisson.getLock("lock:order:close:" + orderNo);
if (!lock.tryLock(0, 10, TimeUnit.SECONDS)) return;   // 别人在处理，跳过
try {
    int n = mapper.casClose(orderNo);            // where status='PENDING'
    if (n == 0) return;                         // 已经关过 / 已支付
    stockMapper.restore(skuId);                 // 回补库存
    redis.zrem("order:delay", orderNo);        // 出队
} finally { lock.unlock(); }

Try-lock with zero wait: if another instance is already on it, skipping is the correct behaviour.等待时间设 0：别人正在处理，跳过就是正确行为。
