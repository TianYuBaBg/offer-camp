Follow-up 03追问 03

Why the list turns into a tree only at 8.为什么链表要到 8 才转红黑树。

Because 8 in one bucket is already statistically impossible for good hashes.因为对正常的 hash 来说，一个桶里挤到 8 个，本就是小概率事件。

Short answer先给答案Under a good hash the chain length follows a Poisson distribution (λ≈0.5): 8 in one bucket happens about 6 in 10 million times. Tree nodes cost more memory, so we only pay that when the hash is clearly bad.hash 均匀时链长近似泊松分布（λ≈0.5）：一个桶里到 8 个的概率约千万分之六。树节点更占内存，所以只有当 hash 明显有问题时才值得付这个代价。

Also note the second condition: the array must be at least 64 long. Below that HashMap resizes instead of treeifying — small tables are cheaper to grow than to convert.还有第二个条件：数组长度至少 64。不到 64 时优先扩容而不是树化——小表扩容比转换便宜。

02Cost of a tree node树节点的代价

  • TreeNode keeps parent, left, right, red/black plus the original next pointer.TreeNode 额外存 parent、left、right、红黑标记，还要保留 next。
  • That is roughly three times the memory of a plain Node, per entry.大约是一个普通 Node 的三倍内存。
  • So the switch is a trade: pay memory only when the chain proves the hash is broken.所以这是一笔交易：只有链长证明 hash 坏了，才付这份内存。
