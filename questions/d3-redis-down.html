Follow-up 03追问 03

Do not let the cache outage become a database outage.别让缓存故障变成数据库故障。

If every request suddenly hits MySQL, the cache being down turns into the whole site being down.如果所有请求瞬间都压到 MySQL，缓存挂就等于整站挂。

Short answer先给答案Three moves: (1) local cache (Caffeine) to absorb reads for a short while; (2) circuit breaker + rate limiter so the DB never sees more than it can take; (3) degrade — read-only pages, or return a friendly “busy, retry” instead of hammering the DB.三步：(1) 本地缓存（Caffeine）先顶一段时间；(2) 熔断 + 限流，保证数据库不会被压垮；(3) 降级——只读页或直接返回友好提示，而不是硬压库。

must know必背3 min3 分钟

01Layers of protection三层保护

  1. Local cache with a short TTL absorbs the first wave.本地缓存 + 短 TTL，挡住第一波。
  2. Sentinel / circuit breaker: fail fast instead of queueing forever.哨兵 + 熔断：快速失败，而不是无限排队。
  3. Rate limit the DB path so a surge cannot take the database with it.对数据库入口限流，避免雪崩式连带故障。

Note what is not on the list: “just restart Redis”. Recovery takes minutes, the traffic does not wait.注意列表里没有“重启 Redis”：恢复要几分钟，流量不会等你。
