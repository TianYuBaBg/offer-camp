CAS plus a per-bucket lock, not a segmented lock.CAS 加“每个桶一把锁”，不是分段锁。

JDK 8 threw away segments: one lock per bucket head, and reads never lock at all.JDK 8 把分段锁扔了：锁的是桶的头节点，读操作完全不加锁。

Short answer先给答案Emptied bucket: CAS to install the first node. Occupied bucket: synchronized on the head node. Reads use volatile reads of the node array and the next pointers, so they never block.空桶：CAS 直接放第一个节点。非空桶：对头节点 synchronized。读操作走数组和 next 指针的 volatile 读，所以从不阻塞。

must know必背3 min3 分钟

01Put, step by stepput 的动作顺序

  1. Bucket empty → CAS the new node in. No lock at all.桶是空 → CAS 放新节点，完全不锁。
  2. Bucket busy → synchronized(head) and walk the chain.桶非空 → synchronize 头节点，沿着链走。
  3. Size uses a base counter plus CounterCell[] to spread contention.size 用 base + CounterCell[] 分散计数，避免所有线程抢一个计数。

02Why not segments为什么不用分段

  • Segments gave at most 16-way concurrency and wasted memory.分段锁最多 16 路并发，还浪费内存。
  • Per-bucket locking scales with the table: more buckets, more parallelism.按桶加锁，并发度随表大小走：桶越多越能并行。
  • Cost: no atomic “size across the whole map” for free, hence the counter cells.代价：整体 size 不再是免费的原子操作，于是有了计数单元。
