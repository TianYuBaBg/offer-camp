Follow-up 08追问 08

Unique is one of seven. Most of the value is in three of them.唯一索引只是七种之一，真正天天用的是其中三种。

Split by purpose first, then by structure. Interviewers usually want the purpose list plus why B+tree won.先按作用分，再按结构分。面试官通常想听作用那七种，以及 B+ 树为什么赢。

Short answer先给答案By purpose: primary (clustered), unique, normal, composite (leftmost prefix), covering, prefix, fulltext. By structure: mostly B+tree; Memory engine has hash; InnoDB adds adaptive hash. Daily work uses primary + composite on query order + covering; every index slows writes.按作用：主键（聚簇）、唯一、普通、联合（最左前缀）、覆盖、前缀、全文。按结构：基本 B+ 树，Memory 引擎有哈希，InnoDB 还有自适应哈希。生产天天用的是主键 + 按查询顺序的联合索引 + 覆盖索引；索引越多写入越慢。

01Seven by purpose按作用分七种

Index索引What it is for干什么用
primary / clustered主键 / 聚簇the table itself in InnoDB; leaf holds the whole rowInnoDB 里就是表本身，叶子存整行
unique唯一enforces uniqueness; NULL is not equal to NULL管唯一性；NULL 彼此不相等
normal (secondary)普通（二级）speeds up lookups, leaf holds the primary key只加速查询，叶子存主键
composite联合multi-column, usable by leftmost prefix多列，按最左前缀生效
covering覆盖all selected columns inside the index, no row lookup查询列全在索引里，不回表
prefix前缀long strings indexed by the first N chars长字符串只索引前几位
fulltext全文inverted index for search倒排索引，做搜索

02Why B+tree wonB+ 树为什么赢

  • Short tree: three or four levels cover tens of millions of rows, so three disk reads.树矮：三四层覆盖几千万行，也就是三次磁盘读。
  • Leaves are linked in order, so range scans and order by read sequentially.叶子有序且相连，范围扫描和 order by 都是顺序读。
  • Hash is O(1) but only equality — no range, no sorting, no leftmost prefix.哈希是 O(1) 但只支持等值——没有范围、没有排序、没有最左前缀。

So: hash for a pure point lookup in memory, B+tree for everything else.结论：纯内存点查可以用哈希，其余一律 B+ 树。

03Clustered vs secondary, in one picture聚簇 vs 二级，一张图

primary key (clustered):   leaf -> (id, name, price, qty, ...)    整行
secondary index on name:   leaf -> (name, id)  ->  拿 id 回主键树再查一次（回表）
covering (name, price):    leaf -> (name, price)  ->  够了，不回表

“Covering” is just a secondary index that already holds everything the query needs. It is the cheapest big win in real systems.“覆盖”就是二级索引里已经带齐了查询要的列——这是线上最便宜的一次大优化。

04The rules that matter in practice实战里真正要记的

  • Build composite indexes in the order you filter: equality columns first, range last.联合索引按查询顺序建：等值列在前，范围列放最后。
  • Each extra index costs write throughput and disk. Keep the ones that earn their keep.多一个索引就多一份写放大和磁盘，只留真正有用的。
  • Watch the plan: explain shows whether the index is used, and “Using index” means covering.看执行计划：explain 里 key 是关键，“Using index” 就是覆盖。
