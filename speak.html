01General phrasing: same thing, two people通用话术：同一件事，两个人怎么说

Do not memorize the whole sentence. Memorize the three bold words in each senior line — then say it in your own order.不要整句背。记住老手那段的三个关键词，然后用你自己的顺序讲出来。

01支付回调重复 —— 你给的那段，我精修过
菜鸟说「微信有时候会重复通知，我在代码里做了个判断，重复的就不处理了。」
老手说因为网络经常会抖动，微信支付可能因为超时重试发来多条回调。为了保证数据一致性，我们在数据库里通过行锁、乐观锁（带状态判断的 SQL），以及给交易号加唯一索引，从而实现了接口的幂等性，保证商品只发一次。
网络抖动超时重试数据一致性行锁乐观锁唯一索引幂等性
  • 先讲原因（网络抖动 → 超时重试），不是先讲自己的代码；面试官听到的是“他理解系统的边界”。
  • 把手段按从强到弱排：唯一索引（数据库兜底）> 乐观锁 CAS > 行锁，说明你知道哪一层最可靠。
  • 最后落在结果（只发一次货），一句话闭环，不拖泥带水。
02缓存和数据库不一致怎么办
菜鸟说「我改数据库之后就把缓存删掉。」
老手说我们走的是 Cache Aside：写库之后删缓存，不是更新缓存。删除失败会进延迟队列重试两次，兜底再靠过期时间；强一致场景不走缓存，直接读主库。
Cache Aside删缓存不更新缓存延迟双删补偿重试过期兜底强一致场景
  • 说清模式名（Cache Aside），面试官立刻知道你不是凭感觉写的。
  • 说清为什么删而不是更新：并发更新会写出脏数据。
  • 给出兜底（重试 + 过期），最后加一句“强一致就不走缓存”——加一句边界，可信度立刻上来。
03穿透、击穿、雪崩，一次说清
菜鸟说「就是缓存不管用了，请求都打到数据库。」
老手说这三种要分开看：穿透是查不存在的数据，每一次都落到库，用布隆过滤器或空值缓存挡；击穿是某个热点 key 过期瞬间被打爆，用逻辑过期 + 互斥重建；雪崩是大量 key 同时失效或 Redis 整体挂了，用随机过期时间 + 集群/本地缓存二级兜底。
布隆过滤器空值缓存逻辑过期互斥重建随机 TTL二级缓存
  • 先分类再给方案，这是老手的肌肉记忆；混着说会显得只是背过。
  • 每类只给一个最常用方案，别堆名词。
  • 结尾点出“三种的根因不同”，显示你理解的是机制不是清单。
04慢 SQL 怎么查
菜鸟说「我加了索引之后就不慢了。」
老手说先看慢查询日志定位 SQL，再用 explain 看 type、rows 和 Extra：全表扫描、filesort、回表太多分别对应不同改法——补联合索引、覆盖索引、或者把 where 条件改成能走索引的形式。改完用压测/线上慢查趋势验证，而不是只看执行时间降了。
慢查询日志explain全表扫描filesort联合索引覆盖索引回表验证
  • 顺序是定位 → 诊断 → 改 → 验证，四步都有，说明你有一套方法而不是零散经验。
  • 说出 explain 里真正要看的字段（type / rows / Extra），比“我用了 explain”强十倍。
  • 强调验证，这是区分“改完就完事”和“对结果负责”的地方。
05分布式锁怎么讲才算讲透
菜鸟说「我用 Redisson 加锁，加锁就没问题了。」
老手说锁的粒度按业务维度定，比如按 sku 加，不是按订单号；持锁时长只覆盖临界区，绝不在锁里做远程调用。Redisson 的 watchdog 负责续期，进程挂了租约自动过期；主从切换可能丢锁，所以最后仍要靠数据库兜底（唯一索引 / CAS）。
锁粒度临界区watchdog 续期租约过期主从切换丢锁数据库兜底
  • 先讲粒度，因为这是最常见的追问点（锁太粗会串行化）。
  • 主动说出锁的失效场景（主从切换），比被问出来强得多。
  • 结尾一定要落到“锁不是最终保证”，这是高级感的来源。
06为什么用 MQ
菜鸟说「用 MQ 可以异步，快。」
老手说三个作用分开说：削峰（下单峰值挡住，消费端按能力拉）、解耦（订单不关心下游有几个）、最终一致（本地消息表 + 重试 + 对账）。代价是重复消费和顺序问题，所以消费端必须幂等，关键业务按业务键分区保证顺序。
削峰解耦最终一致本地消息表对账重复消费幂等分区顺序
  • 讲作用讲三条就够，每条一个词，不展开成长篇。
  • 主动说代价（重复、乱序），并给出对应的解法——这是从“会用”到“负责”的分水岭。
  • 提到对账，说明你想的是“最终一定对得上”，不是“发出去就算完”。
07限流降级怎么做
菜鸟说「我们加了限流，超过就拒绝。」
老手说限流按维度分层：网关层挡总量、服务层按接口/用户挡突刺、核心链路单独配额；算法上单机用令牌桶平滑突发，集群用 Redis + Lua 保证原子。降级要提前定好哪些能力可以关（评论、推荐、非核心查询），并留开关和演练记录。
限流维度令牌桶Redis + Lua 原子独立配额降级开关演练
  • 先分层维度，再说算法，最后说降级——顺序本身就体现设计思路。
  • 说“提前定好”和“演练”，面试官会认为你经历过真实的流量事件。
  • 避免说“超过就拒绝”，那句话听起来像没考虑用户体验。
08线上出问题，你怎么排查
菜鸟说「我看了日志，发现是空指针，改了就上线了。」
老手说先看监控和告警确认影响面（哪个接口、多少量、从几点开始），再从链路追踪定位到具体节点，用日志和复现缩小范围；先止血（开关、回滚、扩容），再定位根因，最后补监控和回归用例，把这次故障变成可预防的。
影响面链路追踪先止血根因补齐监控回归用例
  • “先止血再根因”是运维常识，说出这句话立刻显得成熟。
  • 顺序里带量化（多少量、几点开始），说明你习惯用数据判断。
  • 结尾一定跟复盘动作，把故障变成系统能力。
09需求评审怎么发言
菜鸟说「这个需求能做，给我三天。」
老手说我先确认三件事：目标是什么（成功指标）、边界在哪（哪些不做）、依赖有哪些（第三方、数据、其他团队）。如果这三件不清楚，评估出来的工期也不可信。另外我建议先做最小可用的一版，上线看数据再加。
成功指标范围边界外部依赖最小可用上线看数据
  • 把“能做/不能做”换成“先确认三件事”，这是资深工程师的默认动作。
  • 强调工期不可信的条件，保护自己也保护团队。
  • 主动提分阶段交付，说明你关注的是业务结果而不是写完代码。
10代码评审说什么
菜鸟说「这个写法不好，改成我这样。」
老手说分成三类说：必须改（正确性、安全、并发问题）；建议改（可读性、命名、重复代码）；可以不改（风格偏好）。每条给出理由和影响，能给出示例代码就给示例，让人看懂“为什么”，而不是只服从我的习惯。
正确性/安全/并发可读性理由与影响示例代码不按个人偏好
  • 分级是 review 的核心技巧，避免把个人偏好说成必须改。
  • 强调“给出理由和影响”，这是协作能力而不是技术能力。
  • 最后一句“而不是只服从我的习惯”，是很多面试官想听到的成熟度。
11汇报工作 / 周会发言
菜鸟说「这周改了十几个 bug，写了几个接口。」
老手说这周主要推订单同步这条线：完成两个接口并对接联调，接口 P95 从 800ms 降到 240ms；风险是第三方对账文件晚到，我准备了本地补数脚本兜底；下周做灰度，先切 10% 流量观察。
主推一条线量化结果风险与兜底灰度下周计划
  • 结构固定：做了什么 → 结果多少 → 风险 → 下一步，十秒讲完。
  • 数字要跟自己的判断一起出现（从多少到多少），而不是罗列工作量。
  • 主动讲风险，比被追问“有问题吗”强得多。
12被问到不会的东西
菜鸟说「这个我没做过」「这个不太清楚」。
老手说这块我没有直接做过，我说下我会怎么验证：先看官方文档里的一致性模型，再用一个最小例子复现；如果时间允许我会先做压测对比再定方案。我比较确定的是结论方向——数据一致性优先，性能可以后补。
没直接做过怎么验证最小复现压测对比结论方向
  • “没做过”+“我会怎么验证”是标准答法，比硬编安全得多。
  • 给出最小验证路径（文档 → 小例子 → 压测），说明你有方法论。
  • 最后给方向性判断，让人看到你不是空手。

02From your own CV: the 15 that will actually be asked从你简历里挖出来的 15 条（最可能被问）

Each card is a line on your CV. If you cannot say the senior version, that CV line is a liability.每张卡对应你简历上的一行。老手那句说不出来，那一行就是负债——面试官一追就露。

13多平台订单（京东/苏宁/政采云）怎么统一
菜鸟说「每个平台写一套接口，京东走京东的，苏宁走苏宁的，if else 判断一下。」
老手说先抽象一个统一订单模型：渠道、渠道单号、买家、商品行、金额、状态。每个渠道一个适配器，只做三件事——拉单、映射到统一模型、回传结果；状态以我们的状态机为准，渠道状态只是映射输入。新增一个平台只加一个适配器，主流程一行不改。
统一订单模型适配器状态机渠道单号唯一键主流程不改
  • 先说模型再说模式名，面试官立刻知道你想过扩展。
  • 「只做三件事」是边界感：适配器不许碰业务规则。
  • 「主流程一行不改」是开闭原则的实际收益，比背概念有说服力。
1450 万条政采云数据怎么爬
菜鸟说「用 WebMagic 爬的，爬完存数据库，每天跑一次。」
老手说按公告分类做分页种子，XXL-Job 分片广播把任务拆到多台执行器，每片自己限速，避免把对方站点打挂。入库按公告号唯一键 upsert，重复爬到不会多一行；单条失败进重试队列，第二天从上次的页码继续，不用从头再来。
分片广播限速唯一键 upsert失败重试断点续跑
  • 先讲怎么拆开跑（分片），再讲怎么不重复（upsert）。
  • 限速这句是在替对方考虑，做过生产的人才这么说。
  • 断点续跑讲的是可靠性，比「爬得多快」值钱。
15微信 Native 支付整条链路
菜鸟说「调微信支付接口，成功了就发货。」
老手说下单先落本地 PENDING 订单和唯一订单号，调统一下单拿 code_url 给前端出二维码。回调验签后三步：幂等表拦重复、状态 CAS 改 PAID、扣库存发货。最后再挂一个对账任务拉账单兜底，回调丢了也能补回来。
验签幂等表状态 CAS对账兜底code_url
  • 按时间顺序讲链路，听完就知道你亲手做过。
  • 主动答「回调丢了怎么办」——这是生产经验的分界线。
  • 对账是加分项，多数人只讲到回调就停了。
16多层级数据权限（集团→区域→站点）
菜鸟说「每个接口里判断当前用户是什么角色，再拼 where 条件。」
老手说用 HandlerInterceptor 加自定义注解：注解上标这个接口管哪张表、哪个字段，拦截器解析当前用户的组织路径，统一拼成 where 条件注入到 SQL 里。业务代码一行权限判断都不写，新增接口只要加个注解。
自定义注解拦截器组织路径统一注入零侵入
  • 讲统一出口而不是「到处判断」，这是架构意识。
  • 零侵入意味着不会漏，漏一个接口就是数据事故。
  • 可以顺势延伸到行级权限、多租户，把话题带上你的主场。
17列表接口 P95 从 800ms 降到 240ms
菜鸟说「加了 Redis 缓存，快了很多。」
老手说分两半看：读的一半是热点数据进 Redis，命中率 92%，数据库只承接 8% 的流量；写的一半是慢 SQL 治理，N+1 合成一次 join、补覆盖索引。两个瓶颈分开治，P95 从 800 降到 240。
命中率 92%P95N+1覆盖索引分开治
  • 数字带口径：P95、命中率，不说「快了好几倍」。
  • 主动拆成读和写两半，说明你不是只会上缓存。
  • 不把功劳全给缓存——面试官最烦「加了 Redis 就快了」。
18Redisson 分布式锁到底锁住了什么
菜鸟说「加个分布式锁，就不会重复扣库存了。」
老手说锁只包临界区：读库存、判断、扣减、写回，几毫秒的数据库操作。key 用业务维度 lock:stock:{skuId}，不是订单号。持锁进程挂了靠 watchdog 停止续租、租约自然过期。所以锁是降冲突，最终正确性还是靠唯一索引和状态 CAS 兜底。
临界区业务维度 keywatchdog锁不是最终保障CAS 兜底
  • 先划边界（只包几毫秒），再说 key 设计。
  • watchdog 要能说出它续的是租约，不是锁本身。
  • 承认锁会失效、要靠数据库兜底，这是成熟度。
19百万级报表 3 秒内返回（Oracle）
菜鸟说「用了 Oracle 存储过程，比 Java 里查快。」
老手说原来是 Java 里多次查询再内存聚合，改成一次存储过程把聚合下推到库内，走分区裁剪加覆盖索引。再把报表拆成「当日增量 + 历史汇总」，常态只算增量。3 秒是 P95，不是平均值。
下推分区裁剪覆盖索引增量+汇总P95
  • 讲清为什么快（下推 + 裁剪），不是「存储过程就是快」。
  • 增量 + 汇总的思路可以复用到任何报表，可迁移。
  • 分清 P95 和平均值，一眼看出你真看过监控。
20模板化表单引擎怎么设计
菜鸟说「每种表单写一个页面，改需求就改代码。」
老手说表单结构存成 JSON：字段类型、校验、字典、布局；前端按 JSON 渲染，后端按 JSON 校验并落成「业务主表 + key-value 明细」。新增业务类型只配数据，不改代码。代价是查询要做行转列，我们用宽表加定时物化解决。
JSON 元数据配置驱动业务主表+明细行转列物化
  • 一句话讲清配置驱动：改数据不改代码。
  • 主动说代价（行转列、物化），这是真做过的标志。
  • 能顺带说出「哪些场景不适合」，可信度再上一层。
21Netty 撑 300+ 台售货机长连接
菜鸟说「用 Netty 连设备，收数据存库。」
老手说一条 TCP 长连接对应一台机器，编解码器处理粘包拆包——长度字段加魔数。心跳 30 秒，两个周期没回就判离线并告警；断线由设备侧重连，服务端用会话表恢复。指令下发查 Map<设备号, Channel>，写失败降级成待办队列，不丢指令。
粘包拆包心跳会话表断线重连降级为待办
  • 粘包拆包是必问点，主动说出来面试官就不追了。
  • 心跳 + 会话表讲的是在线状态管理，不是「连上了就行」。
  • 写失败降级成待办，说明你考虑过指令不能丢。
22UDP 组播收设备状态 + 链路智能切换
菜鸟说「用 UDP 收设备状态，收到就存库。」
老手说设备状态是广播型数据，一份数据发给一组接收者，所以用组播而不是点对点，50 台设备只发一次。允许丢包——下一轮状态就覆盖了，所以不上 TCP 重传。链路切换是打分制：信号质量、带宽利用率、误码率加权，超过阈值才切，避免来回抖。
组播容忍丢包打分制加权阈值防抖
  • 先解释为什么是组播，而不是先说技术名。
  • 讲清「为什么可以不管丢包」，比背 UDP 特性有说服力。
  • 打分制 + 阈值防抖，是工程判断，不是教科书答案。
23热搜榜怎么实时算（Redis 有序集合）
菜鸟说「用 Redis 存热搜，定时刷新一下。」
老手说阅读、评论、转发各给权重，分钟级增量累加到有序集合的 score；榜单直接 ZREVRANGE 取 Top N。过期靠分片 key，每小时一个，旧的分片自然淘汰，不用扫全量。热度做指数衰减，避免老新闻永远挂在榜上。
权重ZSet 增量ZREVRANGE分片 key指数衰减
  • 权重 + 增量是算法层，ZREVRANGE 是实现层，层次清楚。
  • 分片 key 解决过期，说明你算过内存和淘汰的账。
  • 指数衰减一句话，就把「老新闻霸榜」的坑补上了。
24基于若依二次开发，怎么讲不显low
菜鸟说「基于若依改的，其实没什么技术含量。」
老手说框架给的是骨架：权限、字典、代码生成。我们在上面做了三件事：认证链改成多端统一（JWT + 拦截器）、数据权限做成注解驱动的行级过滤、供应商侧独立出准入与结算域。骨架省掉 60% 的样板代码，剩下的全是业务域建模。
骨架业务域建模认证链注解驱动行级省 60% 样板
  • 先承认框架的价值，再讲你加的东西，姿态稳。
  • 「剩下的全是业务域建模」把话题拉回你的强项。
  • 别贬低自己用过的框架，面试官会怀疑你看不起业务。
25十秒自我介绍（十年经验）
菜鸟说「我有十年经验，做过很多项目，什么都能干。」
老手说我做了十年 Java，一直做 B 端：订单与支付链路、燃气采购的资源与权限、设备侧长连接监控。最近两年在订单系统上把日单量从 3000 做到 7500，支付链路做到可回调、可对账。这套东西换到你们的业务里，基本能直接用。
B 端支付链路权限可对账直接可用
  • 先说领域再说年限，十年是背景不是卖点。
  • 一个数字胜过十个形容词（3000 → 7500）。
  • 结尾落到「对你们能直接用」，把自我介绍变成解决方案。
26空档期 / 为什么离职
菜鸟说「上一家不干了，休息了一阵。」
老手说上一段项目今年 8 月收尾，我离职后两个月没闲着：把支付幂等、订单状态机、缓存一致性这几块重新梳理了一遍，也写了小工具做验证。现在找的是能长期做的 B 端业务，不想再频繁换。
项目收尾主动补齐可验证长期
  • 给空档一个具体内容，而不是「休息」。
  • 「可验证」很关键——说学了什么，最好有东西能看。
  • 结尾说稳定性，正面回应招聘方最担心的事。
27你最大的缺点是什么
菜鸟说「我比较追求完美，做事太认真。」
老手说我容易一头扎进实现，需求边界没确认就开工，有一次因此返工。现在开工前先写三行：谁用、什么场景、验收标准是什么，跟业务对一遍再动手。
真实事例根因机制化改进
  • 「追求完美」是套话，面试官听腻了。
  • 给一个真实但不致命的缺点，再给已落地的改法。
  • 重点在「现在怎么做」，展示复盘能力。
