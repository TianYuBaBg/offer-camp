Why is HashMap not thread-safe?为什么 HashMap 是线程不安全的？

Two threads write at the same time, one write is lost. In JDK 7 it could even bend into a circle.两个线程同时写，就会丢掉一次写入；在 JDK 7 里甚至能把链表拧成一个圈。

Short answer先给答案HashMap is not thread-safe because put is a multi-step write: two threads can overwrite each other's size, lose a node, and in JDK 7 even bend a list into a circle so get loops forever. In a web app use ConcurrentHashMap, which locks only one bucket.HashMap 线程不安全，因为 put 是多步写入：两个线程会互相覆盖 size、丢掉节点；在 JDK 7 里甚至能把链拧成环，让 get 永远转不出来。Web 应用里用 ConcurrentHashMap，它只锁一个桶。

Basics基础concurrency并发must know必背

01The idea先有一个画面

Think of it like this先这样想Two people write on the same whiteboard at the same time. Both read “size = 10”, both write “size = 11”. One item was added, but the number only went up by one — the other add is invisible.两个人在同一块白板上同时写。两个人都读到 size = 10，都写下 size = 11。 明明加了两个，数字只涨了 1——另一次写入消失了。

put is not one instruction. It is a series of steps: pick a bucket, read the head, write the new node, increase size. Another thread can jump in between any two steps.put 不是一条指令，而是一串步骤：选桶、读头节点、写新节点、size++。另一个线程可以在任意两步之间插进来。

02Three ways it breaks三种坏法

  • Lost update — two puts increase size, one increase is overwritten. The map says 1 item, there are 2.丢更新——两次 put 各涨一次 size，被覆盖掉一次：表里说有 1 个，实际有 2 个。
  • Data lost — two threads add to the same empty bucket; one node overwrites the other.丢数据——两个线程同时往同一个空桶放，一个节点把另一个覆盖掉。
  • Broken list / infinite loop — JDK 7 head-insert during resize could make a circle, then get spins forever.链坏掉 / 死循环——JDK 7 扩容时头插法可能把链拧成圈，之后 get 永远转不出来。

Java 8 changed resize to keep the order (no circle), but data loss and wrong size still happen. “No circle” is not “thread-safe”.Java 8 把扩容改成保序（不会再成环），但丢数据和 size 不准依然存在。“不成环”不等于“线程安全”。

Answers参考答案
01Both threads read 10 and write 11. Two nodes were added, but the number went up by one.两个线程都读到 10、都写 11。实际加了两个节点，数字只涨了 1。
02It used head insertion, so the list was reversed during resize. Two threads could make a node point back — a circle.扩容用头插法，链表会被倒置；两个线程同时做，就可能让某个节点指回去，形成环。
03ConcurrentHashMap: one bucket is locked at a time, so reads stay fast and writes stay safe.ConcurrentHashMap：一次只锁一个桶，读照样快，写也安全。
