What is O(1), O(n), O(log n)?

Big O tells you how the work grows when the data grows. That is all it is.

Basicscomplexity

01The idea

Think of it like thisGuess a number from 1 to 100. Each guess halves the range. 50? lower. 25? higher. You find it in about 7 guesses. That is what log n feels like.

Big O answers one question: when the data grows, how much more work do I do? It ignores small details and keeps only the shape of the growth.

02Four shapes

Big ONameWork when n = 1,000,000Example
O(1)constant1 stepread array[500]
O(log n)logarithmicabout 20 stepsbinary search, balanced tree
O(n)linear1,000,000 stepswalk a linked list
O(n²)quadratic1,000,000,000,000 stepstwo nested loops

HashMap is O(1) on average because it computes the bucket directly — no walking. When a bucket is a line, the worst case is O(n); after the tree, it is O(log n).

03How to read the notation

  • n — how many items you have.
  • O(1) — the time does not change with n.
  • O(n) — twice the items, twice the time.
  • O(log n) — double the items, add one step.
RememberBig O is not about seconds on your laptop. It is about the shape of the cost when the data grows.
