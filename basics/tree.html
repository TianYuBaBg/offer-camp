Lesson 3 · Data structure

What is a tree? And a red-black tree?

An upside-down family tree. A red-black tree is one that keeps itself short.

Basicsdata structure

01The idea

Think of it like thisA family tree, upside down. One person at the top (the root). Their children below. Each child has children below. To find a person, you go down level by level.

A tree is made of nodes, like a linked list, but each node can point to two children: a left child and a right child. A tree like that is called a binary tree.

  • root — the top node.
  • leaf — a node with no children.
  • height — how many levels the tree has.

02Why height matters

If the tree is balanced (left and right are about the same size), the height grows like log n. With 1,000,000 nodes the height is about 20. So finding a value takes about 20 steps, not 1,000,000.

If the tree is not balanced, it becomes a line — and then it is just a slow linked list again.

03What is a red-black tree

A red-black tree is a tree that fixes itself after every insert and delete. It paints each node red or black and rotates the branches, so the height can never grow too much. The rule of thumb: the height stays around 2 × log(n). That is why lookup is O(log n) and never falls back to O(n).

RememberLinked list = a line. Tree = a short, wide shape. Red-black tree = a tree that keeps itself short.

04Where HashMap uses it

Inside HashMap, one bucket is usually empty or holds a short linked list. But if one bucket collects 8 items or more (and the table has at least 64 buckets), that bucket is turned into a red-black tree. So a very bad bucket goes from O(n) back to O(log n).

That is the whole reason the tree appears in the HashMap story: a safety net for bad luck.
