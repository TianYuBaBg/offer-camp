Lesson 4 · Hash

What is a key? A hash? A collision?

A key is the name you search by. A hash is a number computed from it. A collision is two keys with the same number.

Basicshash

01Three words: key, hash, bucket

Think of it like thisYour name is the key. The school gives you a student number computed from your name — that is the hash. The classroom with that number is the bucket.
  • key — the thing you look up by. For example "apple".
  • hash — a number computed from the key. Same key, same number, every time.
  • hash function — the machine that turns a key into a number.
  • bucket — one box in the array, chosen by the hash.

In HashMap the bucket number is computed like this:

index = (n - 1) & hash

n is the number of buckets (16 by default). The result is always between 0 and n-1, so it always points at a real box.

02What is a collision

Two different keys can produce the same bucket number. That is a collision.

key "apple"  → hash 97  → index 1
key "grape"  → hash 97  → index 1   ← same box: collision

03Why we must deal with collisions

Because a bucket holds items in a line (a linked list). If ten keys land in one bucket, finding one of them takes up to ten steps — O(n) instead of O(1). One bad bucket can make the whole map slow.

So HashMap does three things:

  1. Spreads the keys with a good hash function, so collisions are rare.
  2. Keeps a short line in the bucket, and grows the array (resize) when it gets crowded.
  3. Grows a tree when one bucket gets 8 items — the worst case becomes O(log n).
RememberA collision is not an error. It is normal. HashMap does not prevent it; it keeps it small.
