HashMap methods, and how to use them

Six methods you use every day, and three patterns that solve most problems.

Basicspractice

01The six methods you will use every day

MethodWhat it does
put(k, v)Add or replace a value. Returns the old value, or null.
get(k)Read the value. Returns null if the key is missing.
getOrDefault(k, d)Read, or give a default when the key is missing.
containsKey(k)True if the key exists. Use it when null is a real value.
remove(k)Delete the key and return its value.
size()How many pairs are inside.
 
Map<String, Integer> price = new HashMap<>();
price.put("apple", 5);
price.put("apple", 6);              // replaces 5, returns 5
int p = price.get("apple");         // 6
int q = price.getOrDefault("pear", 0);   // 0, no exception
boolean has = price.containsKey("pear"); // false

02Three real patterns

1. Count things

Map<String, Integer> count = new HashMap<>();
for (String word : words) {
    count.merge(word, 1, Integer::sum);   // add 1, or create with 1
}

merge is the shortest way to count. Old style was get, plus one, then put.

2. Group things

Map<Character, List<String>> byLetter = new HashMap<>();
for (String name : names) {
    byLetter.computeIfAbsent(name.charAt(0), k -> new ArrayList<>()).add(name);
}

computeIfAbsent creates the list only when needed. Without it you would write an if (list == null) every time.

3. A small cache

Map<Long, User> cache = new HashMap<>();
User u = cache.computeIfAbsent(id, this::loadFromDb);

Read from the map; if the key is missing, load it and remember it. Note: this is not thread-safe, so use ConcurrentHashMap in a web application.

03Two traps

  • get returns null when the key is missing. If a real value can also be null, use containsKey to tell the two apart.
  • Mutable keys are dangerous. If you change a key object after put, its hash changes and get cannot find it any more. Use immutable keys like String or Long.
